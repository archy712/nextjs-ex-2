# 노션 기반 견적서 관리 시스템 MVP PRD

## 🎯 핵심 정보

**목적**: Notion에 입력된 견적서 데이터를 클라이언트가 로그인 없이 웹에서 바로 조회하고 PDF로 저장할 수 있게 한다.
**사용자**: Notion으로 견적서를 작성하는 1인 사업자/소규모 팀, 그리고 링크를 받아 견적서를 확인하는 클라이언트.

## 🚶 사용자 여정

### 견적서 발행자 (Notion에서 직접 작업, 앱 화면 없음)

```
1. Notion "견적서" 데이터베이스에 새 페이지 생성
   ↓ 클라이언트명 / 유효기간 / 항목(Items 데이터베이스와 관계로 연결) 입력

2. Notion이 페이지 ID 기반 조회 URL을 수식(Formula) 속성으로 자동 계산
   ↓ 해당 셀 값 복사

3. 카카오톡/이메일 등으로 클라이언트에게 링크 수동 전달
   ↓ (서비스가 자동 발송하지 않음 — 앱 범위 밖)

4. 완료 — 이후 Notion에서 내용을 수정하면, 클라이언트가 다시 열람할 때 항상 최신 데이터로 표시됨
```

### 클라이언트 (견적서 수신자, 실제 앱 사용자)

```
1. 전달받은 견적서 링크 클릭
   ↓ 견적서 조회 페이지 접속 시도 (ID 형식 검증 + Notion 데이터 조회)

   [정상 조회]        → 견적서 조회 페이지 → 내용 확인
   [ID 형식 오류/미존재] → 오류 페이지 (404)
   [Notion API 장애]   → 오류 페이지 (503)
   ↓

2. (정상 경로) 견적서 조회 페이지에서 클라이언트명·항목·금액 등 확인
   ↓ PDF 다운로드 버튼 클릭 (브라우저 인쇄 기능 실행)

3. 인쇄 대화상자에서 "PDF로 저장" 선택
   ↓

4. 완료 → 같은 페이지 유지 (필요 시 재확인/재저장 가능)
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | Notion 데이터 조회 | Notion API로 견적서 1건과 연결된 항목 목록을 조회 | 이 서비스의 유일한 데이터 소스 | 견적서 조회 페이지 |
| **F002** | 견적서 내용 표시 | 클라이언트명, 유효기간, 항목별 수량/단가/금액, 합계 금액을 화면에 표시 | 클라이언트가 견적서를 확인하는 핵심 기능 | 견적서 조회 페이지 |
| **F003** | PDF 다운로드(인쇄) | `window.print()`와 인쇄 전용 스타일로 화면을 그대로 PDF로 저장 | 클라이언트가 견적서를 보관/제출하기 위한 필수 기능 | 견적서 조회 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F010** | 견적서 ID 형식 검증 | URL의 견적서 ID가 유효한 Notion 페이지 ID 형식인지 확인 | 잘못된 요청을 Notion API 호출 전에 조기 차단 | 견적서 조회 페이지, 오류 페이지 |
| **F011** | 존재하지 않는 견적서 안내 (404) | ID 형식은 맞지만 Notion에 해당 견적서가 없거나 접근 범위 밖일 때 안내 | 잘못된/만료된 링크에 대한 명확한 피드백 | 오류 페이지 |
| **F012** | 서비스 장애 안내 (503) | Notion API 오류·응답 지연 시 별도 안내 표시 | 데이터 소스 장애와 "존재하지 않음"을 구분해 혼동 방지 | 오류 페이지 |
| **F013** | 반응형 레이아웃 | 모바일/태블릿/데스크톱 화면 대응 | 클라이언트가 어떤 기기로 링크를 열어도 확인 가능해야 함 | 견적서 조회 페이지 |

### 3. MVP 이후 기능 (제외)

- 발행자용 로그인/회원가입, 관리자 대시보드 (견적서 목록/통계)
- 견적서 상태 관리 워크플로우 (승인/거절/대기 추적)
- 이메일/카카오톡 자동 발송
- 견적서 링크 만료·비밀번호 보호
- 부가세·할인 등 세부 금액 계산 (합계 금액만 다룸)
- 다국어 지원, 견적서 템플릿 커스터마이징, 버전 관리

## 📄 페이지별 상세 기능

### 견적서 조회 페이지

> **구현 기능:** `F001`, `F002`, `F003`, `F010`, `F013` | **접근 방식:** 고유 URL (인증 불필요)

| 항목 | 내용 |
|------|------|
| **역할** | 클라이언트가 고유 링크로 견적서 내용을 확인하고 PDF로 저장하는 유일한 조회 화면 |
| **진입 경로** | 발행자가 전달한 견적서 링크 클릭 (예: 견적서 조회 페이지 + 고유 ID) |
| **사용자 행동** | • 클라이언트명·유효기간·항목별 금액·합계 금액 확인<br>• PDF 다운로드 버튼 클릭<br>• 인쇄 대화상자에서 PDF로 저장 |
| **주요 기능** | • ID 형식 검증 후 Notion에서 견적서+항목 데이터 조회<br>• 발행일, 유효기간, 항목별 수량/단가/금액, 합계 금액 렌더링<br>• 인쇄 전용 스타일(`@media print`)로 다운로드 버튼 등 불필요한 UI 숨김<br>• **PDF 다운로드** 버튼 (클릭 시 `window.print()` 실행) |
| **다음 이동** | ID 형식 오류/존재하지 않는 견적서 → 오류 페이지(404), Notion 장애 → 오류 페이지(503), PDF 저장 완료 → 같은 페이지 유지 |

---

### 오류 페이지 (404 / 503)

> **구현 기능:** `F010`, `F011`, `F012` | **접근 방식:** 자동 표시 (사용자가 직접 이동하지 않음)

| 항목 | 내용 |
|------|------|
| **역할** | 잘못된 견적서 링크 접근과 Notion 장애 상황을 구분해 안내하는 오류 전용 화면 |
| **진입 경로** | 견적서 조회 페이지 진입 시 ID 검증 실패, 견적서 미존재, 또는 Notion API 오류가 감지되면 자동 표시 |
| **사용자 행동** | • 안내 메시지 확인<br>• 발행자에게 올바른 링크를 다시 요청 |
| **주요 기능** | • 404: "견적서를 찾을 수 없습니다" (ID 형식 오류·미존재·접근 범위 밖 모두 포함)<br>• 503: "일시적으로 서비스를 이용할 수 없습니다. 잠시 후 다시 시도해 주세요" (Notion API 오류/지연) |
| **다음 이동** | 별도 이동 없음 — 사용자가 올바른 링크를 다시 받아 재접속해야 함 |

## 🗄️ 데이터 모델

> Notion을 유일한 데이터 저장소로 사용하며 별도 DB에 복제하지 않음(읽기 전용). 라인아이템은 페이지 내부 표가 아닌 **하위 관계형 데이터베이스**로 표현해, 합계 금액을 Notion이 자동 계산(Rollup)하도록 한다.

### Invoices (견적서)

| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | Notion 페이지 고유 ID (조회 URL에 사용) | String (UUID) |
| invoice_number | 견적서 번호 (제목) | Title |
| client_name | 클라이언트명 | Rich Text |
| valid_until | 유효기간 | Date |
| items | 견적 항목 목록 | Relation → Items |
| total_amount | 합계 금액 (항목 금액의 합) | Rollup (Sum) |

### Items (견적 항목)

| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 항목 고유 ID | String |
| description | 항목 설명 (제목) | Title |
| quantity | 수량 | Number |
| unit_price | 단가 | Number |
| amount | 금액 (수량 × 단가) | Formula |
| invoice | 연결된 견적서 | Relation → Invoices |

## 🛠️ 기술 스택 (최신 버전)

### 🎨 프론트엔드 프레임워크

- **Next.js 16.2** (App Router, Turbopack) - 이 저장소에 이미 설치된 프레임워크
- **React 19.2** - UI 라이브러리
- **TypeScript 5.9** - 타입 안전성 보장

### 🎨 스타일링 & UI

- **TailwindCSS v4** (설정 파일 없는 CSS-first 엔진, `app/globals.css`의 `@theme inline`) - 유틸리티 CSS
- **shadcn/ui** (`radix-ui` 패키지 기반, `style: "radix-nova"`) - `components/ui/*`의 `table`, `card`, `badge`, `skeleton` 등 재사용
- **Lucide React** - 아이콘 라이브러리

### 📝 검증

- **Zod 4.4** - 견적서 ID 라우트 파라미터 형식 검증, Notion 응답 매핑 검증에만 사용
- `react-hook-form`/`@hookform/resolvers`는 패키지로 남아있으나 이 서비스엔 사용자 입력 폼이 없어 사용하지 않음

### 🗄️ 데이터 소스

- **Notion API** (`@notionhq/client` 최신 버전, 신규 설치 필요) - 견적서/항목 데이터 조회 전용 (쓰기 없음)

### 📄 PDF 생성

- **브라우저 인쇄 기능** (`window.print()` + `@media print` CSS) - 별도 서버사이드 PDF 라이브러리 없이, 견적서 조회 페이지 화면을 그대로 인쇄 대화상자를 통해 PDF로 저장

### 🚀 배포 & 호스팅

- **Vercel** - Next.js 최적화 배포 플랫폼

### 📦 패키지 관리

- **npm** - 의존성 관리

## ✅ 정합성 검증 결과

- 기능 명세(F001~F013)의 모든 항목이 메뉴 구조와 페이지별 상세 기능(견적서 조회 페이지, 오류 페이지)에 매핑됨
- 메뉴 구조의 모든 항목이 페이지별 상세 기능에 존재하며, 참조하는 기능 ID가 기능 명세에 모두 정의됨
- 페이지별 상세 기능에 기재된 구현 기능 ID가 기능 명세와 완전히 일치함 (누락/고아 항목 없음)
